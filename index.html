Design rules

How to build a Figma file that we can turn into a website. Written for designers. You do not need to know anything about code to follow it; where a rule exists because of what the code needs, the rule says so in one line.

Why these rules exist

We build the website from your Figma file with our coding tool, called the kit below. The kit copies what it finds. It does not guess what you meant:

  • a spacing of 19px becomes 19px in the code
  • a colour with no variable becomes a raw value that nobody can change later
  • a box you placed by dragging breaks on the first screen size you did not draw

Your Figma file is the specification. Every rule below exists because breaking it means a question for you or a fix by hand later. Following the rules saves both of us that time.

Check your file with the Design Check plugin

You do not need to learn every rule before you start. The Design Check plugin checks the file for you and shows what to fix.

  1. Install the plugin once. It needs the Figma desktop app: plugins cannot be installed in Figma in the browser

    Download the plugin (.zip)

    1. Unzip design-check-plugin.zip. Put the design-check folder somewhere it can stay, such as your Documents folder. Figma loads the plugin from this folder every time, so do not delete or move it.

    2. Open the Figma desktop app, and open any design file.

    3. Click the Figma menu at the top left, then choose Plugins → Development → Import plugin from manifest…

    4. Choose manifest.json inside the design-check folder. The plugin is installed.

    To update the plugin, download the new zip and replace the design-check folder with the new one, in the same place. You do not need to import it again.

  2. Open your design file and run Plugins → Development → Design Check

    The menu is the Figma logo at the top left.

  3. Choose one page or all pages. If your developer gave you the list of agreed fonts, enter it in Agreed fonts
  4. Click Check design. Every page gets a level, L0 to L3 (see Readiness levels)
  5. Click a page to see what to fix. Click a finding to jump to that layer, and click a rule ID to read the rule
  6. Fix, run the check again, and the level goes up

The plugin checks up to L3. Most of L4 is copy, links and motion, which a person signs off. Your developer runs the same check from the command line when the file is ready, and keeps that report with the project.

Readiness levels

The level says what the kit can do with the page, so it is also the answer to "is the design ready?". A page reaches a level when every MUST rule at that level and below passes.

Level Meaning What the kit can do
L0 The kit cannot find the pages or the sections Nothing. A person reads the file by hand
L1 Pages and sections are findable Draft the sitemap, analyse the design
L2 Built with Auto Layout, colours and text on variables and styles Generate the desktop layout
L3 Small-screen frames exist and match the desktop; assets export cleanly Generate both widths in one pass
L4 Copy is final, links and states are defined, motion is described Build and deliver without going back to the designer

L3 is the target for starting code. L4 is the target for handing the design over. Below L2, the code is written by hand from screenshots, and it costs more and takes longer.

How to read a rule

  - **AL-03** · MUST · L2 · tool — Text boxes are never fixed height …
     └ id       └ severity └ level └ who checks it
  • ID. The plugin reports a finding as VAR-01, and you find the rule here by its ID. IDs never change
  • Severity. MUST — breaking it stops the work or produces a wrong page. SHOULD — the right default; if you break it on purpose, add a note in the file saying why
  • Level. The readiness level the rule belongs to
  • Who checks it. tool — the plugin finds it, and a finding keeps the page below the rule's level. tool(part) — the plugin points at places that are probably wrong; look at each one and decide. These do not lower the level. people — the plugin cannot see it, so check it yourself

The IDs are separate from the ones in coding-rules.md, which are for developers.

Checklist

The short version. Every item links to its rule.

  • Each page is one frame per width, named by its URL: /, /service/web — FILE-01
  • Sections are direct children of the page frame, full width, named section-… — FILE-04
  • Every section, and every group inside it, uses Auto Layout — AL-01
  • Spacing is gap and padding, never spacer boxes or dragging — AL-02
  • Every colour is a variable — fills, strokes, text, gradient stops, shadows — VAR-01
  • Every text uses a text style, in a web font the project loads — TXT-01
  • Anything on two pages is a component; buttons and links have a Hover variant — CMP-01
  • Every desktop page has a small-screen frame with the same sections and the same copy — SP-01
  • Every image and icon has a real name and exports as one piece — AST-01
  • A picture made of several layers is one frame with an export setting — AST-07
  • A thumbnail or article photo is a single image layer — AST-08
  • No dummy copy; every button knows where it goes — CPY-01
  • Everything that moves has a written note — SPEC-01

FILE

How the kit finds your pages and sections. If these fail, nothing else can be checked.

  • FILE-01MUSTL1checked by the plugin Name each page frame by its URL path. The top page is /, the others are /about, /service/web, /news/detail. Lowercase, English, hyphens. The kit finds pages only by this name; a frame called TOP or サービス詳細 is invisible to it
  • FILE-02MUSTL1checked by the plugin One frame per page per width. Exactly one desktop frame and one small-screen frame carry a given path. An old version, an alternative or a draft is renamed so its name no longer starts with / — about (old), about option B — and is best moved to a page called Archive as well. Two frames named /about means the kit has to guess which one is real
  • FILE-03MUSTL1checked by the plugin Use the same artboard widths everywhere. One desktop width (for example 1440 or 1920) and one small-screen width (390 or 375) for the whole file. A small-screen frame is anything narrower than 768
  • FILE-04MUSTL1checked by the plugin Sections are direct children of the page frame. Each one is a frame that spans the full page width, named section- plus what it is: section-kv, section-news, section-faq. The header and footer are instances of the header and footer components (CMP-01), not sections
  • FILE-05MUSTL1checked by the plugin Sections do not overlap. They stack top to bottom, and their order in the layers panel is their order on the page. When the next section has to sit on top of the previous one (a card pulled up over a hero image), do that inside one section with a negative margin or an absolute child (AL-05), never by making two section frames overlap
  • FILE-06MUSTL1checked by the plugin Frames fit their content. A section frame hugs its content (Auto Layout, height Hug). A frame 300px taller than what is inside it is measured as 300px of empty space and built that way
  • FILE-07SHOULDL1checked by a person Keep the working pages clean. Put components on a page called Components, notes and specifications on Spec, and anything old on Archive. The kit reads the whole file; everything you leave on a working page, it has to decide about

Auto Layout

This is the rule that decides most about the code. An Auto Layout frame translates directly into a CSS layout: the kit reads the direction, the gap and the padding, and the browser does the rest, at every screen width. A frame without Auto Layout only has coordinates — "this box is at x=347" — and a developer has to guess what you meant by them. The guess is often wrong, and it is wrong again on every screen size you did not draw.

What your setting becomes in the code:

In Figma In the code What it means for the page
Auto Layout, horizontal a flex row items sit side by side
Auto Layout, vertical a stack items sit one under another
Gap between items gap the space stays exact when content changes
Padding padding the space inside the box stays exact
Wrap flex-wrap a row of cards flows onto a second line when it runs out of room
Space between justify-content: space-between first and last item pinned to the edges
Alignment (the 9-dot grid) align-items / justify-content centred means centred at every width
Width Fill container grows to fill the box stretches with the screen
Width Hug contents fits its content the box is as wide as its text
Width Fixed a fixed width the box stays that size — and overflows a narrower screen
Absolute position child position: absolute taken out of the flow, placed on top
Frame, no Auto Layout coordinates only a developer guesses
  • AL-01MUSTL2checked by the plugin Every section uses Auto Layout, all the way down. The section frame, the content inside it, each card, each row of cards, each button. The test: select any frame that holds more than one thing — it should show Auto Layout in the right panel. The only exceptions are pictures — an illustration, a diagram, a visual composed of several shapes and photos — which are exported as one image (AST-07)
  • AL-02MUSTL2checked by the plugin Space is gap and padding, never objects. No empty rectangles or empty frames used as spacers, no items positioned by dragging. If two things are 40px apart, that 40 is the gap of the frame that holds them
  • AL-03MUSTL2checked by the plugin Text boxes are never fixed height. Set text to Auto width for short labels and Auto height (fixed width) for paragraphs. A fixed-height text box clips or overflows as soon as the copy changes, and copy always changes
  • AL-04MUSTL2flagged by the plugin Choose Fill, Hug or Fixed on purpose. Content columns and cards in a row are Fill; buttons, tags and labels are Hug; only things that really have one size — an icon, a logo, an avatar — are Fixed. A card set to Fixed 427px is built as 427px and does not shrink on a laptop screen
  • AL-05MUSTL2flagged by the plugin Absolute position only for real overlap. Decoration behind the content, a badge on the corner of a card, a label over a photo. Use Absolute position on a child inside an Auto Layout frame, so the rest of the frame still flows. Never absolute-position ordinary content just to put it somewhere
  • AL-06MUSTL2checked by the plugin Use frames, not groups, for layout. A group has no Auto Layout, no padding and no size of its own. Groups are fine inside artwork that is exported as one image, and nowhere else
  • AL-07MUSTL2flagged by the plugin One content width, built the same way in every section. A full-width section frame (Fill) holds a content frame of the project's content width (for example 1200 or 1280), centred by the section's alignment. Do not centre content by adding left padding that happens to add up
  • AL-08SHOULDL2checked by the plugin Repeated items share one parent. Three cards in a row are three children of one horizontal Auto Layout frame with one gap — not three frames placed next to each other. Six cards in two rows are one frame with Wrap on, not two rows. This is how the kit knows they are a list
  • AL-09SHOULDL2checked by the plugin Resize to test. Before handing over, drag the width of a section narrower and wider. If things overlap, jump or leave gaps, the code will do the same. This one minute finds most of the AL rules above

Variables and styles

A value with a name can be changed in one place. A value without one is copied into the code as a raw number, and the next change has to find every copy.

  • VAR-01MUSTL2checked by the plugin Every colour is a colour variable. Fills, strokes, text, gradient stops, and the colour of every shadow. No hex values typed into the panel. This includes a colour used only once: it still gets a variable
  • VAR-02MUSTL2checked by the plugin Every variable has a value. A variable that exists but resolves to nothing is not a colour — the kit reports it and stops
  • VAR-03MUSTL2checked by the plugin No near-duplicates. #1A4FD0 and #1A4FD1, or one blue as a variable and the same blue typed as hex somewhere else, are one colour. Use the variable in both places
  • VAR-04MUSTL2checked by the plugin Gradients are paint styles, and their stops are variables. A gradient used twice is one style, not two copies with slightly different angles
  • VAR-05MUSTL2checked by the plugin Shadows and blurs are effect styles. One visual effect, one style. The same card glow at 15% on one page and 20% on another is either two deliberate styles with two names, or one style used in both places
  • VAR-06SHOULDL2checked by the plugin Spacing and radius come from a scale. Keep number variables for spacing (for example 4, 8, 12, 16, 20, 24, 32, 40, 60, 80) and radius, and use them. A gap of 19 next to a gap of 20 is almost always a slip, and the code copies the slip
  • VAR-07SHOULDL2checked by a person Name variables by role or family. color/primary, color/gray-900, color/text-muted, space/40. The names become names in the code, so a name that says what the colour is for outlives a name that says what it looks like

Text

  • TXT-01MUSTL2checked by the plugin Every text uses a text style. Font, size, weight, line height and letter spacing all come from the style. A text with local overrides is a new style nobody named
  • TXT-02MUSTL2checked by the plugin Only fonts the website can load. Agree the font list with the developer before you start, and use nothing else. System fonts on your machine — SF Pro, Arial, Hiragino, Helvetica — do not exist on the visitor's machine, and the page falls back to something else with a different width
  • TXT-03MUSTL2checked by the plugin Only the agreed weights. Every weight is a separate file the visitor downloads. If the project loads 400, 500 and 700, a 900 in the design renders as a fake bold
  • TXT-04MUSTL2flagged by the plugin Text is live text. Never outline text, and never put text inside an image. Text in an image cannot be translated, searched, read by a screen reader or edited by the client
  • TXT-05SHOULDL2checked by a person Line height and letter spacing are set in the style, in % or px, and the same role uses the same style on every page. A heading tracked 3% on one page and 5% on another is two styles or one slip

Components

  • CMP-01MUSTL2checked by the plugin Anything used on two pages is a component, placed as an instance and never detached. Header, footer, buttons, tags, cards, breadcrumbs, the CTA band. The kit turns one component into one piece of code; two copies become two pieces of code that drift apart
  • CMP-02MUSTL2flagged by the plugin The same block with different text is the same component with overridden text, not a duplicated frame. When a block looks the same on two pages but is not, make the difference a variant or a property
  • CMP-03MUSTL4checked by the plugin Everything clickable has its states. Buttons, links, tabs, cards that are links: a component property named State with at least Default and Hover, and Current, Open, Disabled or Focus where they apply. A button with no hover state is built as a button that does not respond
  • CMP-04MUSTL4flagged by the plugin Open states are drawn. The menu open, the drawer open, the language switcher open, the accordion open, the modal. If it opens, draw it open once. Put these frames on the Components or Spec page
  • CMP-05SHOULDL2checked by a person Components live on the Components page, grouped in sections. Instances on page frames point there

Small screen

  • SP-01MUSTL3checked by the plugin Every desktop page has a small-screen frame with the same path name (FILE-01). If a page will have no small-screen design, write that down (SPEC-02) so it is a decision and not a gap
  • SP-02MUSTL3checked by the plugin Same sections, same names, same order. section-news on the desktop frame is section-news on the small-screen frame. The kit pairs them by name
  • SP-03MUSTL3flagged by the plugin Same content. The same copy, the same number of items, the same people on the same cards. Content that is really hidden on small screens is marked with a note (SPEC-01), not just left out. A missing item, a duplicated card or a card with another card's details is easy to miss when the frames are drawn separately — compare them side by side
  • SP-04MUSTL3checked by the plugin Same variables and styles. A paragraph that is color/black on desktop and color/gray-900 on small screen is two colours in the code. If it is meant to differ, both are still variables and the note says why
  • SP-05SHOULDL3flagged by the plugin The small screen is complete. A small-screen frame much shorter than its desktop frame usually has something missing: stacking makes a page taller, not shorter

Assets

The kit exports images and icons straight from your layers, and the file name comes from the layer name. The client receives those files.

  • AST-01MUSTL3checked by the plugin Name every image and icon for what it is. Lowercase English, hyphens, general to specific: icon-arrow-right, logo-partner, hero-visual, case-study-thumbnail. Figma's default names — Group 123, Frame 456, Rectangle 4, image 11, Vector — become file names nobody can read
  • AST-02MUSTL3flagged by the plugin One asset, one node. Each icon, logo or illustration is a single frame or component that exports as one file. An icon made of five loose vectors placed next to each other exports as five files, or not at all. Put it in one frame and give the frame an export setting (AST-07)
  • AST-03MUSTL3flagged by the plugin Every asset exports. Right-click, export, and check the file comes out. A node that returns nothing — often a mask, a boolean or a video fill — cannot be put on the page
  • AST-04MUSTL3checked by the plugin No invisible layers. Delete hidden layers, 0% opacity shapes, empty frames and fully transparent rectangles. The kit cannot tell a forgotten layer from a deliberate one
  • AST-05SHOULDL3checked by a person Photos are cropped by their frame and are high enough resolution for 2×. A 600×400 photo box needs a source at least 1200×800
  • AST-06SHOULDL4checked by a person Deliver final images, not layout comps or stand-ins. A comp that ships by accident is a problem the developer cannot see
  • AST-07MUSTL2flagged by the plugin A picture made of several layers is one frame with an export setting. A hero visual, a diagram, an illustration, a photo with shapes and effects laid over it: anything the page shows as one picture. Wrap all its layers in one frame, name the frame (AST-01), and add an Export setting to it in the right panel (PNG 2× for anything with a photo, SVG for pure vector art). The export setting is the signal: the kit writes that frame as one image and never looks inside it. Without it, the kit rebuilds every small shape as its own element, and a simple picture becomes dozens of boxes in the code. You do not need to Flatten. Flattening cannot be undone and loses your source layers; the export setting keeps them editable. Text that is part of the picture itself (a label inside a diagram) may stay inside it; text that is page copy may not (TXT-04)
  • AST-08MUSTL2flagged by the plugin A thumbnail or article photo is a single image layer. Post thumbnails, news images, case-study photos — any picture that changes with the content — are one rectangle or frame with an image fill, cropped by that frame. The client will upload a different photo for every post, so the code has one image slot and nothing else. A badge, a category label, a "NEW" mark or a frame drawn over the photo is the same for every post: keep it as its own layer next to the image, not inside it, so it stays live on top of whatever photo the client uploads. Never build a thumbnail out of several small pictures layered together

Copy and links

  • CPY-01MUSTL4flagged by the plugin No dummy copy. No ダミー, lorem ipsum, 20xx.xx.xx, テキストが入ります or repeated placeholder paragraphs. The kit never invents copy, so dummy text is built as dummy text. Where the client still owes the copy, say so in a note (SPEC-02)
  • CPY-02MUSTL4checked by a person Proofread. The code reproduces every character. A missing particle or a typo in the design ships in the page, and is asked about as a question later
  • CPY-03MUSTL4flagged by the plugin Every button and link knows where it goes. Add a prototype link to the target page frame, or a note with the URL. # is not a destination. An external link says so
  • CPY-04SHOULDL4checked by the plugin Mark the page's main heading. Name the text layer of each page's one main heading h1. The largest text on the page is not always the main heading, and only you know which one is
  • CPY-05SHOULDL4checked by a person Text is readable on its background. Normal text needs a contrast of 4.5:1, large text 3:1. Check the lightest point of any gradient or photo that text sits on, not only the darkest

Behaviour notes

A frame is a picture; the page moves. Nothing that moves is in a frame, so it has to be in a note.

  • SPEC-01MUSTL4checked by a person Everything that moves has a written note. A carousel: autoplay or not, speed, loop, what the dots do. An accordion: which item is open first. Scroll animation: what, when, how long. A menu: how it opens and closes. "Like the prototype" is not a note unless the prototype actually does it. Put the note next to the frame (a Dev Mode annotation or a sticky) or on the Spec page
  • SPEC-02MUSTL3checked by a person Say what is not finished. A diagram still to be drawn, copy the client owes, a page with no small-screen design: draw a clearly labelled placeholder box (TBD — diagram), and list it on the Spec page. An unfinished thing nobody mentions is found by the developer, late
  • SPEC-03SHOULDL4checked by a person Page title and description. The text for the browser tab and for search results is not on any artboard. Give it per page, on the Spec page
